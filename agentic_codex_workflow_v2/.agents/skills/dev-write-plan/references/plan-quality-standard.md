# Plan 质量标准

## 必须回答的问题
- 这次任务到底要解决什么问题？
- 哪些内容在范围内，哪些明确不做？
- 已拍板事项是什么？哪些仍需用户拍板？
- 实现必须满足哪些契约、边界、不变量？
- 为什么这种阶段拆分可执行、可验证、可复核？

## 好 Plan 的标准
- **完整但不臃肿**：足以指导实现与评审，但不掺流水账
- **规格导向**：写清 what / constraints / verification，不替代 workflow 状态记录
- **可审查**：reviewer 能直接给出 PASS / NEEDS_CHANGES
- **可执行**：worker 能按 phase 推进，不需要大量自行补设定
- **可回滚**：高风险任务必须显式写清迁移与回滚

## 反例
- 只写“方案概述”，没有 phase 级别的 Verify / Evidence
- 只写实现思路，没有边界、契约、错误策略
- 把 issue 或 workflow 的内容整段复制到 Plan
- 在 Plan 中写执行日志或临时状态
