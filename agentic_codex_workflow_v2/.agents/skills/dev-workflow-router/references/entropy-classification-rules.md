# 熵值判定规则

## Low-Entropy（必须全部满足）
- 变更范围小，通常 <= 3 个文件
- 不新增依赖、不改构建/CI、不改迁移路径
- 不改 public API / 对外契约
- 验收标准明确且可快速验证
- 不需要独立 reviewer 才能显著降低风险

## High-Entropy（命中任一则进入）
- 需要方案设计与阶段拆分
- 涉及多模块 / 多目录 / 多阶段联动
- 影响架构边界、生命周期、依赖方向、公共契约
- 涉及权限 / 安全 / 数据迁移 / 外部集成 / 并发一致性
- 需要新依赖或明显影响部署 / CI
- 执行中发现未知数较多，需要先探索或 PoC 才能继续

## Override / Upgrade 协议
### 强制 override 为 High 的情况
即使表面上满足 Low，也必须走 High：
- 风险高但不体现在代码行数上
- 需要独立评审才能降低风险
- 需要用户拍板后才能继续

### 执行中从 Low 升级到 High
出现以下任一情况立即升级：
- 影响范围超过预期
- 发现对外契约、迁移、依赖或架构边界问题
- 现有验收方法不足以支撑独立复核

### 审计要求
升级 / override 发生时，必须在 workflow 的 `Handoff Snapshot` 记录：
- 原因
- 影响范围
- 下一步验证 / review 动作
